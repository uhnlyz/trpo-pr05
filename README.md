# Практическая работа № 5 — PHP ООП: классы и модели предметной области

## Результат
Небольшой каталог товаров, построенный на объектной модели. Классы `Product` и `Category` описывают предметные сущности, а `CatalogService` загружает исходные JSON-файлы и выполняет операции над коллекцией.

## Реализовано по заданию
- Классы `Product` и `Category` с типизированными свойствами и конструкторами.
- Проверка начальных значений в конструкторах через `InvalidArgumentException`.
- Предметные методы `isActive()`, `belongsToCategory()`, `priceAfterDiscount()`, `availabilityLabel()` и `formattedPrice()`.
- Связь товара и категории по `category_id`.
- `CatalogService` читает `products.json`, `categories.json` и `class_requirements.csv`.
- Сервис формирует массив объектов `Product`, фильтрует каталог, рассчитывает количество активных товаров и среднюю цену.
- HTML получает объекты и вызывает их методы; модели не содержат HTML.
- GET-фильтр по категории.
- В интерфейсе отображаются все 12 записей, включая неактивные товары.
- Есть проверка некорректного конструктора.

## Требования и запуск
Нужен PHP 8.0 или новее. Composer и сторонние библиотеки не нужны.
Из корня проекта выполните:
```bash
php -S localhost:8000 -t public
```
Откройте `http://localhost:8000`.

## Как проверить
1. Убедитесь, что отображаются 12 товаров и три категории.
2. Выберите категорию — список отфильтруется через GET-параметр `category`.
3. Проверьте статусы: исходный JSON содержит активные и неактивные товары.
4. Посмотрите таблицу требований к классам из `class_requirements.csv`.
5. Посмотрите блок проверки конструктора: некорректный объект должен быть отклонён.
6. В блоке расчёта показана работа метода `priceAfterDiscount()`.

## Источники данных
Названия товаров, цены, категории и признаки активности сохранены в исходном виде. Они читаются из предоставленных `dataset/products.json`, `dataset/categories.json` и `dataset/class_requirements.csv`. Поэтому в интерфейсе оставлены исходные названия «Товар 1», «Товар 2» и т. д.

## Подключение классов

Классы подключаются через `require_once`, чтобы один и тот же файл не подключался повторно. Для небольшого учебного проекта это просто и понятно. Когда классов становится много, список ручных подключений начинает разрастаться; в большом проекте обычно используют автозагрузку классов, например Composer.

Поле `active` дополнительно взято из `products.json`: оно нужно, чтобы показать состояние товара. Обязательные свойства `Product` и `Category` сверены с `class_requirements.csv`.

## Схема взаимодействия
```text
products.json + categories.json + class_requirements.csv
                         ↓
                  CatalogService
                         ↓
             массив объектов Product
                         ↓
                   index.php
                         ↓
                 HTML-каталог
```
`Product` отвечает за один товар и его поведение. `Category` описывает категорию. `CatalogService` загружает данные, создаёт объекты и выполняет операции над каталогом. `index.php` отвечает за запрос и HTML-представление.
